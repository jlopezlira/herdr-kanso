## P14 Worktrees: scanning, failing, elsewhere, and a new one

### Worktrees guidelines

- **Seijaku** The scan's progress takes the scope slot ("checking 12 of 40") instead of an 11 phase label squeezed beside the icons. The first scan uses the kit skeleton. Later scans keep the last result and draw Clean up disabled until the scan is done.
- **Yūgen** Empty: "No worktrees".
- **Seijaku** Failures follow P00: the scan's failure sits where the list would start, with Refresh and Explain to checkout; a refused removal sits on its row, with Remove and Explain to checkout, and the row's path and other links step aside.
- **Seijaku** On another computer (an addition): the panel follows the focused project's computer, so the scope says devbox and every command runs there. Unreachable: the kit stale line, writes disabled.
- **Kansō** New worktree is the dialog the sidebar already has, on the dialog skeleton: title 15 semibold, no paragraph, the branch field focused, the folder it will make as a live fact under it, the agent to start (the last one used is preselected), Create solid, Cancel quiet, Enter and Esc. One dialog, two ways in: + here and "New agent in a worktree…" on the project row.
- **Kokō** Create uses solid, not accent: accent is only for a second press.
- **Kokō** Remote calls: one scan per open or Refresh (git worktree list, a status per worktree, sizes), on the computer in scope. No poll. Create is one git worktree add and a new tab.
