## D10 Markdown window and review

### Markdown window and review guidelines

- **Kansō** The window takes the panel skeleton (board 08): header 40, title 20 (the window is 560), ‹ only when a file is open, Close last. Source and Refresh show while the pointer is over the header. The bar under the header goes.
- **Yūgen** The scope line carries the folder, and the save state only while it matters ("Saving…", "Edited"; saved is the rest state and is not said), or the stale line, or "612 KB, read only". Before, the save state was a fourth item in the header.
- **Yūgen** Review: the scope line names who waits ("cart-ui waits for your review"), and Done is the one solid primary, in place of a bordered chip with a tooltip.
- **Kansō** Telling md-review fails: the kit failure under the scope, md-review's own words, then Done (the write's own name) and Explain to cart-ui. The header's Done is not drawn while the failure shows, so there is one Done.
- **Yūgen** "Read again" and "Retry" become Refresh. The tooltip says when it was read.
- **Kansō** Changed on disk while you edit is drawn as P03's editor conflict: one line "Changed on disk at 14:06", then Overwrite and Reload, one press each; after Overwrite the line says "Saved over the 14:06 text" with Undo.
- **Kansō** List: Waiting for your review, From this terminal, In this folder, as panel sections without counts; rows 32. Empty: "No Markdown in ~/infra". The Cmd-click tip goes.
- **Yūgen** Blocks keep their hover (a double-click edits). An editing block is the raised slab with the kit's focus ring. A table edits as its grid.
- **Seijaku** Same document as Preview in the side panel: one MarkdownDoc, two places. The words match Preview's.
- **Kokō** Remote: one stat every 10 s while the window shows, and a full read only when size or mtime changes. Nothing while hidden. The list is read once, on open.
