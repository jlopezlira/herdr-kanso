### First screens guidelines

- **Kansō** Subtract information, never options. At rest a panel drops facts that repeat or say nothing now: scope lines, second lines, labels, marks and colour with no reason. Those facts come back under the pointer or keyboard. Every action and option, those the app has and those we added, stays visible and one press away. Colour stays only on what asks for you, and failures stay loud.
- **Seijaku** Measured in the browser on the six first screens: rows 103 → 76 · glyphs 35 → 19 · colours 33 → 25 · lines 150 → 88. Preview's 14 lines are the file itself, so its chrome is what halves: 2 rows to 1.
- **Kansō** One fact, one place. The folder, branch, files and lines are in the pane header, so the panels drop their scope and facts lines. Header icons, the period switch, Reply and Comment fields, Everyone's, Explain, Remove all and Prune all stay.
- **Kansō** Nothing is lost: each removed fact says where it lives now, and the options audit lists every control. Both are in panels-a-elements.md.

### Pull request list guidelines

- **Kansō** The list is the panel. One list of open pull requests, by project; no hero, no scope line: the pane header already says the branch.
- **Yūgen** The branch in front comes first. With no pull request its row leads and offers Create; with one, the panel opens on it.
- **Seijaku** Every row is the kit's two-line row: title 12.5, number and state as meta 11.5, the verdict word in its state colour and nothing else coloured (K,).
- **Kokō** Cost: one gh pr list per project on open or Refresh; zero at rest.

### Pull requests guidelines

- **Seijaku** First read: the kit skeleton in the list's shape. Later reads keep the rows and spin Refresh.
- **Seijaku** Empty is one line, "Nothing open". If the branch in front has something to say, its row stays above it, and the line becomes "Nothing else open".
- **Seijaku** Signed out and GitHub CLI missing are the only whole-panel states, and both are about this computer, which reads GitHub. Sign in opens gh auth login in a pane to the right.
- **Seijaku** Rate limited and not answering use the kit stale line, with the last rows at 55%. Nothing retries sooner than GitHub's retry time.
- **Seijaku** On devbox: the list doesn't change. The branch row names the computer, and Pull runs there. When devbox is unreachable, only that row dims, with the time it was read; the rest is GitHub's and stays live.
- **Shizen** "Everyone's" reads in place: your rows stay and the others' rows breathe below them.
- **Kansō** A pull request that asks you opens on Your review: one field, Approve, Request changes, Comment. One that belongs to no pane explains to the agent of the pane in front, never a GitHub link.
- **Kansō** A merged pull request leaves the list. Its branch row says so once ("#139 merged 14:20") until the branch changes, and offers Create pull request.
- **Shizen** The branch's pull request paints at once from the header's read; only the card breathes.

### Pull requests guidelines

- **Seijaku** The same three panels as 06, in light: the list on background, the log, threads and fields on canvas. State colours stay the state's; never a new red.
- **Seijaku** The "Everyone's" group open, the review and every thread state are drawn in light on.

### Pull request guidelines

- **Seijaku** Every state that is not mergeable says why, on the card, in its source's words, and has one action that hands that reason to an agent: Explain to \<agent\>.
