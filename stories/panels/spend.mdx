### Spend guidelines

- **Kansō** At rest only what you would miss: header icons appear with the pointer in the panel or keyboard focus; the scope line goes, and a panel's one qualifier (another computer, the month, the device, 1 of 3) sits beside the title in dim; second lines and row actions appear on pointer or selection; folds keep their word. States that need you are unchanged.
- **Fukinsei** The month per plan comes first: one number and one sentence per subscription, for the calendar month, both at rest: 25× "Claude Max 20x: $5,012 of work for $200". Work is the month's sessions of that CLI at API list price; the plan is its monthly price. Under 1× the number and sentence turn working and say "not paying for itself", at rest.
- **Kansō** Detected, not typed. Each CLI's plan is read from one field, never a token: Claude Code ~/.on → oauthAccount.organizationRateLimitTier (default_claude_max_20x → Max 20x) with billingType (stripe_subscription); no oauthAccount means an API key. Codex ~/.codex/on → auth_mode only (chatgpt or apikey; the file's tokens are not read), and the plan from its newest session log, ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl → payload.rate_limits.plan_type (plus, pro). Codex records the plan only once a session has run. Grok ~/.grok/on → payload.settings.subscription_tier_display (SuperGrok Plus); subscription_tier is empty, and Grok's price is not recorded. Pi records no plan: it runs on API keys.
- **Yūgen** Prices per plan come from a list shipped with kansō (new, on): Claude Pro $20, Max 5x $100, Max 20x $200; ChatGPT Plus $20, Pro $200; SuperGrok $30, SuperGrok Heavy $300. Checked each release. A plan not in the list says so and takes your price in place.
- **Seijaku** No plan: API key use is plain cost, "paid as used", with no multiple.
- **Seijaku** Month just started: before the 7th, the number is the pace in dim, "too early to say".
- **Yūgen** Several computers: each computer's sessions are priced there and summed here, one line per computer; an unreachable one says so under it. The same Claude account on two computers (oauthAccount.accountUuid, an id) counts its plan once.
- **Shizen** Settings: sources are on when their folder holds sessions; a missing CLI says "not on this computer". Plans are detected rows, corrected in place (Enter keeps it; the correction is pending until saved). Add plan stays for what cannot be detected.
- **Kansō** One fact, one home: the multiple lives here only. The status bar's spend item stays the day's number.
- **Seijaku** States follow: first read, empty, a read failed, a plan not read on its row.
- **Kokō** Cost: three small local files, read when the panel opens and once an hour after. Another computer: its plan and its month's rows come over the existing sync exchange, one call per synced computer per minute while the panel is open and in front, under 2 KB; nothing when closed.
- **Seijaku** New to build: the detector (three readers), on, a Grok session reader (Spend reads Claude Code, Codex and Pi, core/), the month-per-plan figure in, the plan row in the sync payload.

### At rest, measured

### Element · before → now · when it appears

- Share, Settings, Refresh: in the header → gone. pointer in the panel or keyboard focus.
- Scope: month, computers, synced: a line → November beside the title. pointer on November: computers and synced.
- Plan sentence ($5,012 of work for $200): a line per plan → unchanged. the fact you would miss: stays.
- Divider: a rule → gone.
- Period switch and arrows: a row of six → the word today. pointer or keyboard on today: the switch in its place.
- Tasks, a task, tokens: a line → gone. pointer on the number.
- Projects / Models switch: a row → gone. pointer on the list.
- Project letter square, tokens line: per project → gone. the name says it; tokens on pointer.
